/01

Sobre mim

A engenharia por trás da conectividade e da nuvem.

Uma trajetória construída na prática: da camada física e roteamento em escala de telecomunicações à arquitetura resiliente na AWS e automação DevOps.

Minha história na tecnologia começou no contato direto com a operação: identificando anomalias de hardware, solucionando problemas em enlaces de rádio, configurando ativos de rede via CLI e garantindo que serviços essenciais continuassem operando sem interrupções.

Ao longo de mais de sete anos no Grupo Brisanet, passei por todas as etapas fundamentais da infraestrutura: do suporte técnico de alta complexidade à engenharia de redes de grande escala, atuando com protocolos de roteamento dinâmico como OSPF e MPLS, ampliação de enlaces Metro e DWDM em Data Centers e participação direta em projetos de expansão tecnológica, incluindo a preparação de infraestrutura para o 5G.

Com a evolução contínua da infraestrutura, direcionei meu foco para a interseção entre redes e software: Cloud Computing, Automação e DevOps. Sou certificado AWS Certified Solutions Architect – Associate (SAA-C03) e aplico diariamente ferramentas como Terraform para Infrastructure as Code, Docker e Docker Compose para isolamento de microsserviços, e Shell Script, Python e Ansible para eliminar tarefas manuais repetitivas.

Acredito em uma engenharia honesta e fundamentada em evidências: projetos bem documentados, ambientes de testes reproduzíveis e respeito rigoroso aos pilares de disponibilidade, segurança e eficiência de custos.

Automação & Provisionamento

Ambientes Locais Idempotentes com Vagrant, Ansible & Nginx

Contexto & Desafio

Dificuldade em manter paridade entre máquinas locais de teste e servidores de homologação, resultando em erros por discrepâncias manuais de pacotes, dependências e configurações de rede.

Minha Contribuição & Solução

Desenvolvimento de arquitetura de provisionamento via código: definição de máquinas virtuais via Vagrantfile e orquestração de configuração através de Ansible Playbooks modulares organizados em roles (incluindo role common e deploy de servidor web Nginx servindo consumo de APIs).

Resultados & Aprendizados

Padronização completa da inicialização de instâncias Ubuntu locais com um único comando (vagrant up), garantindo idempotência e eliminando o retrabalho em setups manuais.

Ansible Vagrant Nginx Ubuntu IaC Local

Containers & Microsserviços

Orquestração Multi-Tier com Docker Compose e Imagens Alpine

Contexto & Desafio

Aplicações com múltiplas camadas (Front-end, Back-end API Node.js e Banco de Dados) necessitavam de isolamento de execução, controle estrito de portas e redução no consumo de recursos em máquinas de desenvolvimento.

Minha Contribuição & Solução

Criação de Dockerfile enxuto utilizando base Alpine Linux para a API NodeJS e composição de stack completa em docker-compose.yaml. Isolamento de serviços através de redes virtuais internas do Docker, mapeamento de volumes para persistência e injeção de parâmetros de ambiente.

Resultados & Aprendizados

Redução significativa do tamanho das imagens finais e capacidade de subir todo o ecossistema com comunicação interna resolvida por DNS de serviço nativo do Docker.

Docker Compose Docker Node.js Alpine Linux Containers

Observabilidade & Monitoramento

Automação de Pilha Zabbix Server e MySQL para Telemetria

Contexto & Desafio

A implantação de servidores de monitoramento para auditoria e teste de ativos frequentemente esbarrava em processos manuais de instalação de pacotes, permissões de banco de dados e execução de scripts de esquema.

Minha Contribuição & Solução

Construção de script Shell modular (config-serv-ubuntu.sh) acoplado ao provisionamento do Vagrant. Automação da instalação do Zabbix Server, criação de banco MySQL, importação autônoma de esquemas SQL estruturados e configuração de daemons de serviço.

Resultados & Aprendizados

Ambiente de monitoramento funcional pronto para receber coletas SNMP e agentes em poucos minutos, com documentação clara do processo de inicialização.

Roadmap · Em Desenvolvimento

Infraestrutura Multi-AZ na AWS com Terraform

Objetivo Arquitetural

Provisionar uma infraestrutura completa seguindo o AWS Well-Architected Framework: VPC personalizada, subnets públicas/privadas em 2 Zonas de Disponibilidade (us-east-1a e 1b), NAT Gateways e Route Tables desacopladas.

Serviços AWS & Tecnologias

Terraform (State remoto no S3 com lock via DynamoDB), Application Load Balancer (ALB), Auto Scaling Group (ASG) de EC2 em subnets privadas e Amazon RDS Multi-AZ.

Entregáveis

Código Terraform modularizado, diagramas arquiteturais em draw.io/Mermaid e estimativa de custos via Infracost.

Terraform AWS VPC ALB & ASG RDS Multi-AZ S3 + DynamoDB
Roadmap · Em Desenvolvimento

Pipeline de CI/CD com GitHub Actions para AWS ECS

Objetivo Arquitetural

Criar uma esteira de entrega contínua com gatilhos automáticos a cada push na branch principal: testes de unidade, scan de vulnerabilidades de imagens com Trivy e deploy sem downtime.

Serviços AWS & Tecnologias

GitHub Actions Workflows, Docker Buildx, Amazon Elastic Container Registry (ECR), AWS ECS com AWS Fargate e integração segura via OpenID Connect (OIDC, sem secrets estáticos).

Entregáveis

Arquivo de workflow YAML auditado, Dockerfile otimizado multi-stage e política de rollback automático em caso de falha de health check.

GitHub Actions AWS ECS / Fargate Amazon ECR OIDC IAM Trivy Scan
Roadmap · Em Desenvolvimento

Cluster Kubernetes Local com Kind & Ingress NGINX

Objetivo Arquitetural

Montar um cluster Kubernetes local multi-node (1 control-plane e 2 workers) utilizando Kind, permitindo testes avançados de balanceamento de carga, políticas de rede e escalabilidade de pods.

Tecnologias

Kind (Kubernetes in Docker), kubectl, Ingress NGINX Controller, Helm para empacotamento de manifests e MetalLB para simulação de LoadBalancer local.

Entregáveis

Configuração do cluster em YAML, Helm Chart customizado para API e roteamento de rotas e certificados locais.

Kubernetes Kind Helm Ingress NGINX kubectl
Roadmap · Em Desenvolvimento

Stack de Observabilidade: Prometheus & Grafana

Objetivo Arquitetural

Construir uma solução unificada de monitoramento e telemetria para servidores Linux e containers Docker, com coleta de métricas via pull e alertas automatizados.

Tecnologias

Prometheus Server, Node Exporter, cAdvisor (métricas de containers), Alertmanager e Grafana para visualização em dashboards interativos.

Entregáveis

Stack orquestrada via Docker Compose, regras de alerta de saturação de CPU/Memória/Rede e dashboards exportáveis.

Prometheus Grafana Node Exporter Alertmanager Telemetria
